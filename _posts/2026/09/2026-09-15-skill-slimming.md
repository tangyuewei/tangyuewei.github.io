> **摘要**：skill 的名字和描述都占着上下文。装得越多，描述越可能被截断，模型越容易选错。现在能测了：Claude Code 的 plugin eval 给每条 skill 算出 Δ，OpenAI 建议把根文档退化成路由表。

大部分人的 skill 库是这么长起来的。

一开始只有一条。你发现 AI 总不按你想的方式写单测，于是写一条 skill 把团队规范固化进去。过两周它总忘记更新 changelog，又加一条。再后来是接口文档格式、SQL 审查清单、发布检查步骤。

半年后回头看，目录里躺着二十几个文件夹。

问题不在数量。问题是你不知道哪几条还在起作用。

有人会说，装了总比没装强。但每条 skill 的名字和描述都要进模型的上下文——模型得先知道自己有哪些能力，才谈得上用不用。这些描述占着位置，而位置是有限的。

更要命的是，**你没法验证它到底做了什么**。

以前评价一条 skill 好不好，靠感觉：今天它好像挺听话。改了描述之后呢？新模型发布之后呢？没人知道。

现在这件事开始有数字了。

## Δ：一条 Skill 到底贡献了什么

9 月 11 日，Claude Code v2.1.269 上线了 `plugin eval`[1](https://code.claude.com/docs/en/plugin-evals)。

它跑一组测试用例，每条用例是一个真实的用户 prompt，配一个或几个 grader——对 AI 的产出做通过或失败的检查：对回复做正则、看某个工具有没有被调用、或者让第二个模型按评分标准判一次。

关键在怎么算分。

每条用例跑两遍：一遍装插件（WITH），一遍不装（W/OUT）。两个分数一减，就是 Δ。默认每臂跑三次，所以一条用例实际是六次运行。

官方文档写得很直白：如果一个用例在装与不装的情况下都拿满分，那通过跟你的插件没关系。

这句话是这个功能的核心。**高分不说明插件的功劳，差值才说明。**

官方给的样例长这样：

```text
CASE        WITH   W/OUT    Δ      RUNS   COST
first-case  1.00   0.33   +0.67     6     $0.41
```

一条 skill 值不值，看 Δ。

## 最常见的体检结果：它压根没被触发

Anthropic 说，最常见的第一个发现是：**Δ 接近零，同时 `tool_used: Skill` 这个 grader 失败**。

翻译过来就是——AI 在自然措辞下根本没有选你的 skill。

这正是老工具看不见的。`claude plugin validate` 检查的是 manifest 的语法和 schema：它告诉你插件包有没有写坏，不告诉你插件有没有改变 AI 的行为。

于是一条 skill 可能语法完美、安装成功、列表里看得见，然后在真实对话里一次都没被调用过。你看不出来，因为你默认它在工作。

修法通常是重写描述，再跑一遍对比。

OpenAI 在同期发的文档里给了个典型改法：

```text
# 改前
创建并验证 Postgres 模式迁移。在处理数据库、查询、模型或持久化时使用。

# 改后
创建并验证 Postgres 模式迁移。在添加或修改迁移文件，或审查其部署上线时使用。
```

改前的写法，会在模型碰到任何数据库相关内容时都跳出来——"处理数据库"这个条件太宽了。改后限定了具体动作：加迁移、改迁移、审迁移。

差别就在这。描述写宽，模型在不该用的时候用它；描述写窄，模型在该用的时候不认得它。而这两件事，以前都只能靠猜。

这里要分清两件事。之前写过上下文窗口越大、模型越容易忘事，那讲的是窗口**里面**：注意力被稀释、中段信息容易丢。这篇讲的是**入口**：描述还没被完整读进去，就已经被截断了。

![体检的两种结果：语法通过但从未触发，validate 看得见语法、看不见行为](/imgs/202609/2026-09-15-skill-slimming-infographic-2.jpg)

## 根文档不是手册，是路由器

OpenAI 的 Codex 团队在《为 GPT-6 Astra 重写 skills 与 prompts》[2](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) 里点破了另一半。

skill 太多的时候，Codex 会开始**缩短**这些描述，好塞进上下文。模型最终只看到每条描述的一部分——信息不完整，就更难判断该选哪条。

注意这个失败模式和"没装"不一样。没装，至少模型知道自己没有这个能力。描述被截断，模型看到的是**残缺的信息**，它会照着残缺的信息做决定。

所以他们对 skill 结构的第一条建议是：把根文档做成一张**最小路由表**。

一条 skill 如果覆盖多个工作流，根文档只写"该去找哪个文件"，细节留给辅助文档和脚本。给模型的信息刚好够它判断去哪看，不要逼它读当下用不上的东西。

理由很直接：读 skill 本身要花上下文，离压缩更近一步，还会带进和当前任务无关的指导。

第二条建议听起来像开倒车——别把 skill 写成一步一步的详细手册。

模型对细节和歧义的理解能力已经强了很多。过去为了防幻觉写的详细步骤，现在反而会拖后腿：本来能自己判断的环节被一条条流程框住，算力就花在满足流程上，而不是写干净的代码。

同样的逻辑适用于 AGENTS.md：

```text
# 改前
每次编辑前，先读 architecture.md、database.md、deployment.md。

# 改后
用 architecture.md 判断服务边界，用 database.md 判断表结构变更，准备部署时看 deployment.md。
```

改一个按钮的拼写错误，不需要先绕项目一圈。

## 提示债：为旧模型写的护栏在拖累新模型

OpenAI 给这件事起了个名字：提示债（prompt debt）。

过去两年，为了让模型不跑偏，我们写了很多东西：冗长的 AGENTS.md、事无巨细的 skill、一层层的"先问我再动手"。那是当时模型水平决定的，是必要的。

但这些指令不会因为你在编辑器里换了个模型端点就消失。它们躺在上下文里，占着位置。

换到新模型上，这些护栏从"保护"变成"限速"。

最反直觉的例子是：连"跑测试并检查结果"这样的指令，也可能该删。新模型自己会跑；你多写一句，它反而可能去做一些没人要求的测试，把时间和上下文花在多余的动作上。

还有一层容易被忽略：仓库里的 skill 不只你一个人在用。它是写给**所有贡献者的 AI** 看的，而那些 AI 可能跑在不同的模型上。

帮 Sol 或 Luna 表现更好的指导，可能正好过度约束了 Astra。写 skill 的时候，得想清楚这份指令将来会被谁读到。

不过这不是让你把所有规矩都拆了。

OpenAI 的建议里有明确的分界：可逆的本地操作可以放开，比如跑本地测试、修相关报错、重跑受影响的用例。但生产访问、破坏性迁移、外部副作用、凭据这四类，审批闸门要留着。

删的是"为旧模型加的无谓护栏"，不是"防止贵重事故的约束"。

## 这笔账要花钱，也可能算错

Δ 听起来很干净，但代价和误差都在。

每一次 eval 运行、每一次 judge grader 都是真实的模型调用，计入你的套餐或 API 账单，官方显示的金额还只是标价估算。

一条用例两个臂各跑三次，再加上 llm、baseline 这两种 grader 要额外调用评审模型——数量涨得比想象快。

好在六个 grader 里有四个是免费的：regex、tool_used、tool_order、file_exists，它们从会话记录和磁盘文件里算，不调模型。想先看效果，别急着上 judge。

更麻烦的是，AI 执行本身有随机性。同一个 skill 跑两次结果不同是正常的——所以要跑三次取均值，所以文档才建议把模型版本钉死，否则前后分数没法比。

还有一种失败会伪装成回归。如果触发了用量上限，跑出来的低分看起来像"skill 变差了"，其实只是没跑完。官方为此专门留了退出码 2，表示这是一次部分运行，结果文件里也会带上标记。

最后一条最容易被忽略：**要测一个插件，你得先信任它。**

eval 把插件跑在隔离的会话里，只加载目标插件——听起来很安全。但插件的 hooks 和 MCP servers 依然以你的用户权限执行。

隔离的是上下文，不是权限。你为了验证一个来路不明的插件跑了 eval，它的 hooks 该跑还是在你的机器上跑了。

命令行里那个 `--trust-plugin` 不是形式主义。

如果这些都想清楚了，它可以进 CI：

```bash
claude plugin eval --trust-plugin \
  --json results.json \
  --threshold 0.8 \
  --model claude-sonnet-5 \
  --judge-model claude-haiku-4-5 \
  --no-publish \
  --max-cost-usd 20
```

一条 skill 的改动，如果让某个用例掉到阈值以下，构建就失败。把运行模型和评审模型都钉死，分数才可比。

## 收尾

回到开头那二十几条 skill。

减肥不是删到最少，是让留下来的每一条都拿得出 Δ。

你不需要一次把整个库测一遍。挑三条你最依赖的，写几个真实 prompt，先跑一次不带 judge 的——六个 grader 里有四个免费。

你会很快发现一件事：**有些 skill 你以为是它在起作用，其实不是。**

这个发现本身，比任何一条 skill 都值钱。
