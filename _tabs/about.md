> **不要迷恋哥，哥只是个传说。**

曾经是一名 **Java 后端工程师**，后来做过架构、技术管理和项目管理，也写过前端、折腾过 DevOps。

现在，我更关心的是一件事情：

> **当 AI 开始参与软件开发，一个工程师到底应该如何重新工作？**

过去，我习惯自己分析需求、设计架构、写代码、调试、测试、上线。

现在，我开始把 **AI Agent 当作软件开发团队的一部分**。

从 AI 辅助 Coding，到 Agent 编程，再到多 Agent 协作、AI Harness、工程规范与自动化验证，我正在持续探索：

**如何让 AI 不只是“帮我写几行代码”，而是真正参与整个软件研发流程。**

我更关注的不是：

> **“AI 能不能写代码？”**

而是：

> **“如何让 AI 持续、可靠、可控地完成软件工程任务？”**

## 🧠 AI Harness Engineering

这是我目前重点研究的方向之一。

如果说 Agent 是“干活的人”，那么 **Harness 就是约束 Agent 如何干活的工程系统**。

我正在尝试把传统软件工程中的：

* 项目规范
* 架构约束
* Coding Standards
* AGENTS.md
* Prompt / Skill
* Workflow
* Verification
* Checklist
* CI/CD
* Memory
* Context Engineering

重新组织起来，形成一套适合 **AI Agent 软件开发** 的工程体系。

核心目标不是写一个更复杂的 Prompt，而是：

> **让 AI 在正确的上下文、正确的规则、正确的流程和正确的验证机制下工作。**

## 🚀 从 Coding 到 AI Engineering

我经历过几个阶段：

```text
传统 Coding
    ↓
AI 辅助 Coding
    ↓
Agent Coding
    ↓
Multi-Agent
    ↓
AI Software Team
    ↓
AI Harness Engineering
```

这个过程中，我越来越确信：

> **AI 编程真正改变的，不是“写代码的速度”，而是软件工程的生产方式。**

未来的开发者可能不再只是一个人写代码，而更像是：

```text
                    ┌── PM Agent
                    │
                    ├── Architect Agent
Developer ── AI ────┼── Coding Agent
                    │
                    ├── Test Agent
                    │
                    ├── Review Agent
                    │
                    └── DevOps Agent
```

工程师真正需要掌握的，也会逐渐从：

> **“如何写好代码”**

扩展到：

> **“如何设计、管理和验证一个由人 + AI Agent 组成的软件工程系统。”**
